# Нотация Big O

## Что такое сложность алгоритма

При разработке важно учитывать не только правильность решения, но и его эффективность. Один и тот же результат можно получить разными алгоритмами, однако время их работы может значительно отличаться.

Для анализа эффективности алгоритмов используется понятие **сложности алгоритма**. Сложность показывает, как меняется время выполнения программы при увеличении размера входных данных.

Размер входных данных обычно обозначается буквой **n**. Например, если алгоритм работает с массивом, то `n` — это количество элементов в массиве.

Для описания поведения алгоритма при больших значениях `n` используют **асимптотическую сложность**.

---

## Что показывает Big O

Нотация **Big O** используется для описания того, **как растёт время выполнения алгоритма при увеличении размера входных данных**.

Важно понимать, что Big O не показывает точное время выполнения программы. Она показывает только **скорость роста времени выполнения**.

Например, если сложность алгоритма `O(n)`, это означает, что время выполнения растёт пропорционально размеру входных данных. Если сложность `O(n²)`, время будет расти значительно быстрее.

Примеры:

- `O(1)` — время не зависит от размера данных
- `O(log n)` — время растёт очень медленно
- `O(n)` — время растёт линейно
- `O(n²)` — время растёт квадратично
- `O(2ⁿ)` — время растёт экспоненциально

---

## Big O и константы

При анализе алгоритмов отбрасываются постоянные множители.

- `T1(n) = 5n`
- `T2(n) = 100n`
- `T(n) = n² + n + 10`

# смотрим сложности

## O(1) — константная сложность

- время выполнения не зависит от размера данных

Что делает функция?
```python
def ?(arr):
    return arr[0]
```

## O(n) — линейная сложность

- время растёт пропорционально количеству элементов

Что делает функция?
```python
def ?(arr):
    val = arr[0]

    for x in arr:
        if x > val:
            val = x

    return val
```
